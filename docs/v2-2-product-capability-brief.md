# SolutionScope v2.2 功能说明

## 它解决的实际问题

技术方案、可研和验收材料中的同一项要求，经常分散在不同章节和不同版本里。普通检索或 RAG 可以找到相关文字，却不会天然判断：

- 方案是否真正承诺了需求指标；
- 验收方法是否能够验证该承诺；
- 材料描述的是当前能力还是后续规划；
- 需求变更后，旧的审核结论是否仍然有效。

SolutionScope 将这些问题转化为可检查的产品流程，而不是继续生成一段更长的答案。

## 当前已经实现的核心能力

1. **三类材料分开登记**：分别处理要求、方案和验收材料，避免检索到相关内容就误判为闭环。
2. **原子要求与证据绑定**：把对象、动作、条件、指标和验收方法拆成固定字段，每个判断都能回到页码、章节和段落。
3. **状态与版本控制**：区分当前、规划、未知和冲突；要求发生修改、拆分、合并或删除后，冻结旧结论并生成复核清单。
4. **确定性指标门禁**：统一百分比、时间和距离等常见单位，再比较指标对象、方向和阈值；方案承诺弱于要求或验收口径不一致时自动阻断。
5. **人工复核动作**：不只标记“有风险”，还明确需要重查方案、重查验收、确认生命周期或补充来源。
6. **浏览器审核工作台**：集中展示原文、结构化要求、三方覆盖、变更影响、阻断原因和人工决定，支持导入本地审核包。

## 与普通 RAG 的边界

| 普通 RAG | SolutionScope |
|---|---|
| 找到相关内容并回答问题 | 判断要求、方案和验收是否形成闭环 |
| 以自然语言答案为主要结果 | 以证据、状态、门禁和复核动作作为主要结果 |
| 新旧版本通常作为两次独立问答 | 维护变更关系并冻结受影响结论 |
| 模型看到相似文本可能判断“已覆盖” | 程序继续核对指标方向、阈值和单位 |
| 信息不足时仍可能补全流畅答案 | 缺口、冲突和证据不足进入人工门禁 |

## 最小可复现功能例子

- 要求：目标识别率 `≥92%`
- 方案：目标识别率 `≥90%`
- 验收：按 `≥92%` 判定

即使模型把方案标记为“完整覆盖”，确定性门禁仍会输出 `solution_threshold_not_satisfied` 并阻断放行。

另一例：要求 `≤600 ms`，方案和验收写作 `≤0.6 s`。系统先进行单位换算，再判断三者口径一致，避免纯字符串比较造成误报。

## 对外表述边界

可以表述为“面向复杂技术材料的要求—方案—验收核验工作台”或“受控 AI 审核工作流”。当前不宣称替代领域专家，也不把冒烟测试写成准确率或泛化证明。
